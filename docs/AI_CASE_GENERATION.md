# AI 用例生成工作流

入口：`/ai-generation/requirement-analysis`。

## 操作流程

1. 选择所属项目，填写需求标题，然后选择“输入需求”或“上传文档”。项目为必填项。
2. 检查右侧生成配置。关闭自动评审时只需要编写模型和编写提示词；开启时还需要评审模型和评审提示词。没有生成行为配置时，默认启用自动评审。任务按创建时选定的评审配置执行，之后修改开关只影响后续新任务。
3. 提交后按任务真实状态展示生成、评审、修订与终态。离开已创建的任务不会取消服务端任务；同一用户可在当前浏览器会话中恢复上次任务，也可从生成记录打开进行中的任务。
4. 完成后优先展示最终用例。编写草稿和评审意见单独查看。“检查与编辑”进入详情页，可修改或选择采纳部分用例。
5. “导入剩余用例到用例库”会实际创建项目草稿用例，不会执行用例；重复导入会跳过已采纳项。页面按用例 ID 显示待导入数量，部分采纳后仍可继续导入剩余项。Excel 下载使用与预览、采纳一致的后端规范化数据。

## 权限与任务配置

项目观察者（`viewer`）可以读取任务和查看实时进度，不能生成、修改、删除、取消、弃用或采纳任务用例。项目负责人、管理员、开发者和测试者按项目写权限操作；系统管理员保留管理权限。未绑定项目的历史任务只允许创建者或系统管理员修改，采纳时还必须拥有目标项目的写权限。

生成任务统一通过 `testcase-generation/generate/` 创建，通用集合 POST 不创建任务。编写/评审模型与提示词由服务端选择，创建后不能用任务 PATCH 改绑配置引用。

## 输入与失败处理

- 新建文字需求支持最多 50,000 字符。恢复任务按原保存格式编辑，使用最多 100,000 字符的请求预算；已保存的标题封装会单独还原，不会在重试时重复拼接。若标题占用预算，修改标题会同步更新正文可用长度，并明确显示超限原因。
- 上传文件支持 PDF、DOCX、TXT、Markdown，最大 10 MB；不支持旧版 `.doc`。
- 扫描 PDF 需要先进行 OCR。损坏、无文字或编码不可读的文档会明确失败，不把错误信息交给模型当作需求。
- 文档提取后的生成请求最多 100,000 字符（包含标题），超出时应按功能拆分。
- 上传、提取和创建任务共用提交锁；相同文件、项目、标题下重试提取会复用已上传文档。
- 创建生成任务前会保存 UUID 提交标识。响应丢失时先按标识查询；重试复用相同标识，服务端按用户去重。刷新或提交期间离开页面后也可恢复。若相同标识对应的需求已改变，服务端返回原任务供检查，不能隐式创建第二个任务。浏览器仅持久化任务 ID 和提交标识，不保存需求正文。
- 取消操作调用服务端取消接口，并清理页面连接。worker 会拒绝取消后的写入；已发往外部模型的推理请求是否立即停止取决于调用阶段及服务方。
- 连接中断会切换为单次请求不重叠的轮询。失败原因保留在页面，草稿可供排查；“编辑需求并重试”会创建新任务，保留原输入。
- 新生成结果必须至少包含有效标题、非空操作步骤和非空预期结果，才能标记完成。采纳接口在写入前执行同一完整性检查，选中任一无效用例会整批拒绝，避免部分写入。历史结果仍可查看和编辑，补齐字段后再采纳；不会自动删除或改写既有业务数据。

## 生成质量策略

流式与完整输出使用同一套范围要求：每条用例对应明确需求，优先主流程和高风险业务规则，减少重复验证点，不按固定比例扩展所有功能。未说明的阈值、权限、错误码和提示文字列为待澄清事项。

评审与修订都会收到原始需求，防止评审建议脱离需求或新增没有依据的规则。输出模式仅影响展示时机。

提示词策略不能代替真实业务验收。此次自动化测试使用模拟 provider，未对线上模型输出质量作出量化结论。

## 验证命令

```bash
python -m pytest apps/requirement_analysis/tests
cd frontend
npm run test:requirement-generation
npm run lint
npm run build
```

覆盖重点：任务模型引用不可改绑、viewer 只读与项目写权限、评审配置开关与排队期间配置变更、私有模型可见性、文档解析失败、项目与输出模式边界、用例字段完整性与采纳原子性、上传防重与提交幂等恢复、取消与迟到回调、部分采纳后导入剩余用例、长文档恢复和标题预算、规范化导出、Markdown 表格安全渲染和重复入库。

发布时需同步更新前端、Django 服务和生成任务 worker。本次不涉及数据模型字段变更。
